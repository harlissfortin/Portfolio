# Swimlane Process Mapping — Working Guide

*Companion to Unit 1.2 and Workshop 1. Frame files ship in Miro/Mural/Lucid/PowerPoint.*

## Symbols (only four)
Oval = start/end · Rectangle = activity (verb + noun) · Diamond = decision (label every
exit) · Arrow = flow (backward arrows are required honesty, not failures)

## Build steps
1. **Lanes:** one per role/department/system that touches the work. If a lane never
   touches the work item, delete it.
2. **Walk the happy path first**, start to end, 8–20 steps, with the people who do the work.
3. **Then add the truth:** decisions with labeled exits, rework loops, workarounds,
   waiting points. Ask at every step:
   - *What happens when this goes wrong?*
   - *Who exactly does this — and do they do anything first?*
   - *How long does work sit before this step?*
   - *Is this the SOP, or what actually happens?*
4. **Validate by walking one real work item** through the real flow within a week.
   Update the map with what you find — the changes are the findings.
5. **Annotate:** ⚡ where errors occur · ⏱ waits (with rough times/ranges) · 🔁 rework
   loops. Then count and record:

| Measure | Count |
|---|---|
| Steps | |
| Handoffs (lane crossings) | |
| Decisions | |
| Rework loops | |
| Total elapsed (typical) | |
| Touch time (typical) | |

6. **Circle one candidate focus** — biggest wait, worst loop, or nastiest handoff — with
   one sentence of why.

## Quality checks
- [ ] As-is, not should-be (contains at least one workaround or honesty artifact)
- [ ] Every diamond's exits labeled; every backward arrow drawn
- [ ] Built and validated with people who do the work — not from an SOP or a memory
- [ ] Right altitude: 8–20 steps ("worlds" boxed for their own later map)
- [ ] Annotations + counts table complete
